# 7Peaks Reads 디자인 — light-v8

한국어 번역입니다. 영문 원본: [README.md](README.md).

기존 [Reads 사이트](https://sevenpeaksone.github.io/reads/)의 확정된 디자인 원본입니다. GitHub Pages 호스팅, 기사 주소, 누적 보관함, 분류, 검색 데이터, 즐겨찾기, 일일 발행 규약을 유지합니다. 기사 파일을 Cloudflare Pages나 R2로 이전하지 않습니다.

## 디자인 원본

- `reads_theme.css`: 별도 다크 스타일 위에 덧붙이는 보정본이 아니라 레이아웃과 디자인 전체의 공통 원본입니다. 아이보리 `#F6F8ED`, 차콜 `#17201B`, 라임 `#D5F43B`, 주황 `#F28B3C`, 보라 `#9270D8`, 녹색 `#2BA978`.
- `reads_theme_init.js` / `reads_theme.js`: 첫 화면 표시 전 밝은 화면 초기화 및 폐기한 테마 버튼·설정 정리.
- `assets/7peaks-a-lockup.webp`: 승인한 A 심볼과 얇은 글자 로고. 다시 그리거나 앞에 7을 하나 더 붙이지 않습니다.
- `reads_article_template.html`: 단독 미리보기용 기사 문서 구조.
- `render_reads_article.py`: 템플릿·스타일·인라인 로고를 사용해 일관되게 조립하는 도구.
- `rebuild_index.py`: 공통 목록·본문 생성기. 사이트에 공통 로고와 `assets/reads-theme.css`도 설치합니다.
- `test_reads_theme.py`: 단독 조립 및 신규 기사 발행 검사.
- `verify_reads_theme.py`: 원본과 디자인 적용본의 본문·이미지 참조·링크·검색 데이터를 읽기 전용으로 비교하는 검사.

Reads 저장소에서는 `tools/reads-theme/`에 있습니다. 기사 제작 프로젝트에서는 같은 리소스가 `docs/`에 있고, 이 가이드의 파일명은 `docs/READS_DESIGN.md` 및 한국어 번역 `docs/READS_DESIGN.ko.md`입니다.

## 회사 디자인과의 일관성

Reads는 세상 이야기를 글로 읽는 별도 서비스이며 회사 홈을 복제하지 않습니다. A 심볼·표시 높이만 줄인 원래 로고·서체·아이보리/차콜/라임 토큰과 시각적 높이 32px의 얇은 조작부만 공유합니다. 작은 제목 영역 다음에 뉴스·블로그 목록이 바로 이어집니다. 회사 홈 사진·슬라이드·홍보 히어로를 Reads에 넣지 않습니다. 선택한 B 이미지는 Reads 홈에만 유지하고 아이보리 배경으로 부드럽게 연결합니다. 블로그·뉴스 첫 화면은 텍스트 전용입니다. 제목·설명·읽기 링크는 유지하되 장식 이미지와 예약된 이미지 열·최소 높이를 없앱니다. 재생성할 때 책·신문 장식 이미지를 다시 넣지 않습니다. 로고는 이미 줄인 중간 시안이 아닌 첫 회사 헤더(433f751)의 정확히 1/3로 표시합니다. 기존 1100px·600px 분기에서 이미지 높이는 약 31.78px·26px·23.11px입니다. 메뉴 글자는 유지하며 콘텐츠 제목·본문은 줄입니다. 주황·보라·녹색은 분류 강조색으로 유지합니다. 검색·즐겨찾기·보기 설정·페이지 이동·읽기 진행률·기사 내용은 보존합니다.

고정 버전 Fontsource 5.3.0 서체 스타일시트 두 개는 jsDelivr에서 불러옵니다. 레이아웃은 로컬이며 오프라인에서는 시스템 서체로 대체합니다. 회사 홈 사진 자산은 Reads에서 사용하지 않습니다. 홈의 읽기 이미지는 assets/reads-world-b.webp입니다. assets/reads-news-paper.webp는 비활성 원본 자산으로 보관하고 뉴스 첫 화면에는 표시하지 않습니다. 기사 이미지의 색상·크기·압축을 바꾸거나 교체·삭제하지 않습니다. 보관된 포인트 필드와 이전 로고 자산은 현재 디자인 원본이 아닙니다.

## 원본과 생성된 HTML

공개 목록과 내용이 있는 모든 기사는 `assets/reads-theme.css?v=light-v8` 및 같은 버전의 공통 스크립트를 참조합니다. 기사 고유 마크업은 유지하고 공통 테마가 표현을 정돈합니다. 단독 미리보기에는 정확히 같은 스타일과 로고 이미지를 포함합니다. 원본 수정·사이트 재생성·제작 프로젝트 동기화를 함께 수행해야 이후 기사도 같은 디자인을 유지합니다.

## 밝은 화면 전용 정책

소유자는 2026-11-17 다크모드를 제거하도록 지시했습니다. 홈·목록·보관함·즐겨찾기·기사 상세는 OS나 예전 저장 설정이 어두움이어도 밝은 디자인으로 표시합니다. 테마 버튼이나 다크 CSS를 생성하지 않습니다. 스타일보다 먼저 문서 head에서 밝은 화면을 적용하고 폐기한 `spk-theme` 키만 지웁니다. 뒤로가기 복원이나 오래된 탭에도 대응합니다. 즐겨찾기·검색·보기 설정 등 다른 저장 데이터는 삭제하지 않습니다. 저장소 사용이 차단돼도 밝은 화면은 동작해야 하며 신규 단독 기사에도 같은 초기화를 사용합니다.

## 앞으로 생성할 기사 조립

기사마다 임의 CSS를 만들지 않습니다. 기존 흐름으로 초안 Markdown을 본문 HTML 조각으로 변환합니다. 문서 태그와 첫 기사 제목 h1은 제외하고 제목을 별도 인수로 전달합니다. 본문, 출처 링크, 날짜, `./images/...` 경로를 보존합니다.

제작 프로젝트에서 실행합니다.

```sh
python3 docs/render_reads_article.py \
  --title "기사 제목" --category "IT" --date "2026-11-10" \
  --body output/topic/body.html --output output/topic/final.html
```

예시 값이 아니라 실제 메타데이터를 사용합니다. 기존 출력은 기본적으로 덮어쓰지 않습니다. 확인·백업한 뒤 필요한 경우에만 `--overwrite`를 추가합니다. 메타데이터를 이스케이프하고 정확한 스타일·로고를 문서에 포함하므로 로컬 미리보기에 외부 스타일시트가 필요하지 않습니다. 내용 검토용 `final.md`도 유지합니다.

최종 문서는 h1 하나, `body[data-reads-view="article"]`, `data-reads-theme="light-v8"`를 사용합니다. 미치환 템플릿 토큰을 남기지 않습니다. 해시태그는 두 번째 h1이 아니라 문단으로 표시합니다. 이미지 내용·상대경로, 의미 있는 대체텍스트, 반응형 크기를 유지합니다. 스타일 때문에 리서치, 편집 원칙, 이미지 제작, 주제를 바꾸지 않습니다. 회사 소개에 미구현 AI·위키 기능을 추가하지 않습니다. AI를 주제로 한 뉴스를 금지하는 뜻은 아닙니다.

## 발행 규약

기존 대기함/READY 방식과 일정을 유지합니다. 제작 측 `site.tgz`에는 **`posts/` 또는 `news/` 아래 기사 폴더와 이미지만** 넣습니다. 최상위 `assets/`나 `tools/`는 추가하지 않습니다. 수신 측 생성기가 공통 에셋을 설치하고, 미리보기용 CSS·탐색을 공통 틀 하나로 바꾸며, 예전 인라인 스타일로 들어온 기사에도 확정된 디자인을 적용합니다.

예정된 모든 기사와 참조 파일을 확인한 뒤 마지막에 READY를 작성합니다. 빈 기사나 부분 완성 묶음을 완료로 표시하지 않습니다. 스타일 적용을 이유로 직접 Git 푸시, 인증·일정·이력 파일 수정, 발행 스크립트 변경을 하지 않습니다. 과거 누락 본문·이미지는 별도 보고하며 임의 작성·삭제·복구하지 않습니다.

## 검사

Reads 저장소 루트에서 실행합니다.

```sh
python3 -B -m unittest discover -s tools/reads-theme -p 'test_reads_theme.py' -v
node --test tools/reads-theme/test_reads_theme_script.mjs
```

대량 생성은 내장 디스크 사본에서 `SITE`를 명시하고 진행하며 외장 SSD에서는 실행하지 않습니다. 뉴스·블로그의 PC·모바일 화면, 이미지 참조, 검색, 즐겨찾기, 페이지 이동, 예전 다크 설정이 있어도 밝게 표시되는지를 확인합니다. 미리보기·원본 설치·커밋·푸시·실제 배포 확인은 구분해서 보고합니다.
